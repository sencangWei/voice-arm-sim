# 2026-10-25：抓碗失败与指令响应慢

本轮修复实际工程 `/home/robot/voice-arm-sim` 的视觉几何抓放路线，未训练或更换 π0.5 权重。控制链为 Qwen3-VL 理解中文及当前图像 → RGB-D 定位 → OSC 通用抓放 → 松爪撤手 → 视觉核对。控制器不读取仿真物体身份、真实位姿或成功谓词。

## 复现的问题与修改

- 原失败记录在 `before/`：`把碗放到盘子上`，122 个控制步后下降未收敛。原图像及语言模型识别正确，但按碗中心夹取，约 11 cm 的碗超过 Panda 约 8 cm 的张开宽度，手指碰到碗沿后持续下压。
- 视觉几何路线误继承旧实验的 CPU 8912 服务，`before/command/model.json` 记录 CPU 推理 26.877 秒。现默认使用已加载 GPU 模型的 8911 服务，并记录请求耗时、首个控制步和运动结束时间。中文面板同步更新说明。
- 宽圆形容器根据可见深度拟合圆沿，改为夹单侧碗沿，放置时保留碗中心与夹取点的偏移；闭爪同时维持抓取目标，避免接触回弹。
- 盘子落点包含与平面相连的浅盘沿，按碗底可见半径留边距；避免只用内平面和统一 6 cm 边距导致无法放置。圆沿拟合保留更完整的倾斜圆弧，原拟合残差、覆盖角等拒绝条件保留。
- 窄瓶放在宽支撑面上时，只以物体上部可见范围判定抓取宽度，避免把瓶底连着的灶台误判为宽容器。

## 实际验证

从原始场景初始化并重放原失败的 122 步，保留失败时的接触状态。随后连续执行以下三条指令，中间不重置：

| 指令 | 无窗口首步等待 | GUI 首步等待 | GUI 整条指令耗时 |
| --- | ---: | ---: | ---: |
| 把碗放到盘子上 | 1.49 s | 1.44 s | 26.09 s |
| 把酒瓶放到灶台上 | 1.19 s | 1.25 s | 21.05 s |
| 把酒瓶放到碗里面 | 1.16 s | 1.28 s | 18.53 s |

无窗口评测 `after/validation.json`：三条全部通过独立物理检查，最后 10 个控制步均满足目标放置关系且没有夹爪接触。该检查只在执行后读取物体真值用于评分，不向控制器反馈信息或改变动作。每条的 `physical-observer.json` 保存检查过程。

GUI 验证 `gui-verification.json`：三条视觉核对全部完成并自动停止。对应原始视频、输入和最终画面、动作轨迹保存在 `gui/command-1` 至 `command-3`。GUI 按控制频率播放；无窗口运行未加实时等待，因此不能用其总耗时代表窗口中的实际动画时长。

`gpu-task-benchmark.json` 对同一个原失败输入测得首次 GPU 请求约 4.01 秒；上表是模型已预热后的观测值，并非所有指令的延迟保证。

回归验证：178 个仿真环境测试与 18 个子测试通过，另一个现有 VLA 环境中 2 个模型产物测试通过；Ruff 与 `git diff --check` 通过。

## 复现命令

先启动现有 GPU 模型服务（8911），在仓库根目录执行：

```bash
.venv-vla-sim/bin/python evidence/response-grasp-20261025/validate_sequence.py \
  --from-failure --output runs/response-grasp-recheck-unique
```

输出目录必须是新目录。窗口版从相同失败现场开始、自动执行三条指令，结束后保留窗口和现场：

```bash
DISPLAY=:0 MUJOCO_GL=glfw __NV_PRIME_RENDER_OFFLOAD=1 \
__GLX_VENDOR_LIBRARY_NAME=nvidia \
.venv-vla-sim/bin/python evidence/response-grasp-20261025/restore_panel.py --validate
```

窗口运行中的记录位于 `.local/response-grasp-20261025/gui-live.json`；本目录的 `gui-verification.json` 是已完成验证的冻结记录。`--followup-scene <已保存的场景目录>` 可在恢复原失败控制后重放该目录的后续动作，重新打开已有现场，不自动执行新指令。

## 边界

证据覆盖一个原失败现场中的三条连续指令，以及同场景的 GUI 复核；不等于任意物体、遮挡、倾倒、堆叠和任意摆放都可靠。宽物体仅支持能可靠拟合的可见圆沿，不满足条件仍会停止并保留现场。此轮属于视觉定位与通用控制修复，不能描述为端到端 VLA 已学会通用抓取或人工纠错训练成功。
